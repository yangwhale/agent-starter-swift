# 活脸移植保真度 —— 逐轮记录

对照对象：AgentTouch 原固件 `face.cpp` + `grokface.cpp`（真代码，垫假 Arduino_GFX 在 Linux 上跑）
vs 我们的 `CCFaceMotion`（docker 里导出绘制清单）→ 照 `CCFacePainter` 逐行写的 Python 光栅器。
同皮肤、同状态、同一个绝对时刻（原固件 `millis()` = 1 000 000 ms ↔ 移植 t = 1000.0 s），30 fps（原固件主循环 `now - lastFrame >= 33`）。

度量：
- **确定性帧**：两边都没在眨眼、且还没到第一次换表情（池子间隔下限）之前的帧 —— 这些帧不含随机数，应当逐帧一致。
  看像素 IoU（阈值 0.1）和**轮廓边误差**（连通块包围盒四条边的最大偏差，px）。
- **随机部分**（眨眼间隔、换表情时刻和选哪张、grok 表情池）：两边随机数发生器不同（原固件 LCG 按开机毫秒播种，
  移植是 splitmix64 按房间名），不可能逐帧对齐 → 比分布（30 次进入 × 120 s，50 fps 采样）。
- **曲线**（眨眼曲线、grok 弹簧）：在事件起点对齐后逐帧比。

## 第 0 轮：先证明基准渲染器本身画对了

- harness：`face.cpp` / `grokface.cpp` 原样编译；假 `Arduino_Canvas` 的 fillRoundRect / fillCircle / drawCircle /
  fillTriangle / **fillArc** / drawLine / 经典 5×7 字模逐行抄自 Arduino_GFX 源码（BSD）。
  `fillArc` 的角度约定由源码决定（0° 三点钟、y 朝下，180→360 是上半圈「∩」）—— 渲染出来 done 的弯眼确实是 ∩。
- 跟 `media/states.gif`（原版宣传动图）对：缩放 400/480、偏移 10 px 后，**idle IoU 0.998、needs 0.999**；
  working 0.941 / done 0.916 是动图那一帧的扫视 / 弹跳相位对不上（在 0–4 s 里找最优帧）。
- 跟 `media/grok.gif` 对：idle 0.985、working 0.949、done 0.991；needs 只有 0.65 ——
  把 harness 的眼睛整体下移 56 px 后升到 **0.960**：动图是设计稿画布出的，没有固件里 `GCFG.dy = -56`
  （给批准气泡让位，「真机 2026-09-13」那次改的）。即 harness 忠实于固件，动图早于那次改动。
- 结论：harness 可作为基准。

基线（r0，移植 d7fb619 原样）：所有皮肤 × 状态的确定性帧 IoU 0.87–0.99，轮廓边误差 ≤ 1–2 px
（原固件整数像素 + `(int)` 截断 vs 移植连续坐标 + 抗锯齿；fillArc/fillCircle 在 Arduino_GFX 里
外径按 r+0.5、内径按 r−0.5 判，所以原版圆环比数学上厚约 1 px）。唯一明显偏低的是 grok needs（0.31），
即上面那 56 px —— 移植有意不移（我们没有批准气泡）。

## 第 1 轮

### 发现

1. **点阵字形抄错了两个**（逐像素对比 + 对 Arduino_GFX `glcdfont.h` 字节）：
   - 「?」第 4 行原版是 `..##.`（`0x59` 列含第 3 行），移植手画成 `...#.`，少一格；
   - 「.」原版在第 3、4 列（`00 00 60 60 00`），移植画在第 2、3 列 —— bored 的「...」整体左偏 3 px。
2. **grok 弹簧曲线不是原版那条**（对齐换表情时刻逐帧比 s_pos）：
   移植用的是微分方程解析解（过冲 3.8%、0.4 s 才落稳）；原固件实际跑的是**每帧 33 ms 拆 3 个 11 ms 子步的
   半隐式欧拉** ＋「>0.999 且 |v|<0.05 贴到 1」，而且**换表情的那一帧里就已经积分了一帧**。
   板子上看到的是：第一帧就走到 0.26、过冲只有 **1.6%**、第 11 帧（0.33 s）贴死。
   - 用 30 fps 跑 harness：原版 `0.265 0.597 0.830 0.953 1.003 1.016 1.014 1.008 1.004 1.001 1.000`
   - 修前移植（解析解，同采样点）：`0.078 0.249 0.446 0.629 0.778 0.889 …` 峰值 1.038
3. 统计部分全部一致（见 `out/r0/stats.txt`）：每个状态的首次眨眼区间（lo·0.4…hi·0.6）、眨眼间隔
   （均值/最小/最大落在 GCFG 区间）、眨眼时长 320 ms、表情池换脸间隔与均匀使用、绝不连着同一张、
   grok 表情池各状态间隔与使用分布 —— 两边差异都在 30 次采样的抽样误差内（另用 400 次移植采样确认首次眨眼
   是 [2, 7.2] 上的均匀分布，均值 4.63 vs 理论 4.6）。

### 修法

- `CCFaceMotion.question` / `.dot` 改成逐位抄 glcdfont（注释里写了字节）；测试：问号 10 个点、省略号点在第 3、4 列。
- `CCFaceMotion.spring`：改成 `springTable` —— 按原固件的积分器、30 fps 推一遍记表，按真实时间在相邻两帧间线性插值；
  测试钉：第一帧 0.2621、峰值 1.012–1.02、第 11 帧贴死。

### 结果（r1）

- 弹簧（`tools/spring_check.py`）：30 fps 下 16 帧最大偏差 **0.003**，峰值 1.0158 vs 1.0158。
  （20 fps 下原版自己就变了 —— 它的曲线依赖帧率，所以以板子真实的 30 fps 为准。）
- bored 确定性帧 IoU 0.948 → 0.960（省略号对齐），needs 的问号轮廓误差从 5 px 降到 ≤1 px。

## 第 2 轮：触发逻辑（什么时候该出哪张脸）

逐条读 `main.cpp`（`faceRender` 前组 `FaceFrame` 那段、lonely sighs、拿起/翻面、按键）和
`host/agentpet_host.py`（席位状态合并），对 `CCFaceMood` / `CCFaceMotion`：

| 原固件 | 触发 | 我们 | 结论 |
|---|---|---|---|
| `visualState()` 优先级 | dizzy > surprised > petting > eating > burp > **listening > offline** > stretch > bored > agent 状态 | 睡着/找人 > 等你 > 在听 > 说话 > 干活 > 干完 > 空闲 | **listening 压过 needs_you 对不上 → 改**（见下） |
| `ST_OFF` | agent 进程没开 → 睡觉 | 灰点（没连/挂断）→ 睡着 | 对应合理；**但「连着而 bot 不在房间」原版是 ST_OFF，我们当成橙点照常判、会拿 bot 走前留下的 wait/on 画脸 → 改** |
| `offline` | `!(hostUp ‖ BLE)`，TCP 35 s 收不到也算 | 黄/红点（正在连、断线重试）→ 迷糊找人 | 一致 |
| `ST_NEEDS_YOU` | host：任一会话 needs_you，合并时压过 working/done | `wait` 非空 | 一致（host 合并顺序 needs > working > done > idle，跟我们的 等你 > 干活 > 干完 > 空闲 同序） |
| `ST_WORKING` | hook 活动，120 s 无声衰减成 idle | `on == true` | 一致（衰减由 bot 端负责） |
| `ST_DONE` | Stop 之后 **90 s**（`DONE_LINGER`），期间又干活就让位 | 3 s 窗口 | **有意不同**：Chris 批的方案写「三秒后回空闲」；注释写明原版 90 s 和取舍 |
| `listening` | 按住语音键 | 按住说话 | 一致；**优先级改成压过「等你」** |
| `bored` | 所有席位闲/关 ＋ 10 分钟没人碰 → 5–60 s 后叹第一口，之后每 2–5 min 一次，每次 4.5 s；一戳就停 | 原来**从不触发** | **能对上就接上 → 改**：这个房间空闲满 10 分钟按同样节奏插 4.5 s bored；只插进空闲（我们的「睡着」是用户自己挂断，不对着人叹气）；没有「戳」 |
| `surprised` | 拿起来 / 翻回正面，700 ms | 不触发 | 有意不同：靠 IMU，app 没有对应的事（注释写明） |
| `petting` | 摸屏幕，每次摸续 800 ms | 借给「在说话」 | 我们独有；评估见下 |
| dizzy / eating / burp / stretch | 摇晃 / 充电 / 充满 / host 提醒休息 | 不触发 | 硬件或 host 功能，app 没有（注释写明） |
| needs_you 抢屏、自动切席位、批准气泡、底部名牌和席位圆点 | — | 不移植 | 板子是多席位单屏，我们一个房间一张脸 |

**「在说话」借 petting 协不协调**：petting 是 ∩∩ 弯眼 ＋ 脸红 ＋ 3 px、0.79 s 周期的轻晃、不眨眼，
grok 用 [2, 17] 两张笑眼每 1.5–3 s 换。持续几十秒也不突兀（一直在轻轻点头），跟「刚干完」的 ∩∩ 弯眼是同一家族，
所以「干完那一刻 bot 立刻开口念总结」时 3 秒 done 窗口被「在说话」盖住，观感上仍是连贯的笑眼，不算冲突。保留。

### 修法

- `CCFaceMood.derive` 加 `botPresent`（必填，不给默认值 —— 漏传会编不过，而不是静默当成在场）；
  `!botPresent → .asleep`；`holding` 判断挪到 `wait` 前面。视图传 `slot.botPresent`。
- `CCFaceMotion`：`boredAfter = 600`、`boredLength = 4.5`、`boredEpisode` / `resolve`：
  空闲里插进来的那一段算一次完整的换状态（眨眼重排、表情池回 V0、grok 从当时那张变过去），叹完回空闲再换一次；
  `grokShowing` 让 `CCFaceClock` 换心情时记下的是「真正在显示的那张」（叹气中途换心情也对）。
  `scene(look:_:)` 拆出来供对照工具画 bored / surprised。
- 测试：Mood 311 条（含 bot 不在的 32 行、优先级链）；Motion 276 条（叹气首次 5–60 s、每次 4.5 s、间隔 2–5 min、
  只插进空闲、since 重算、grok 交接）。10 条针对新规则的变异 10 杀 0 漏。

### 结果

- 用 harness 的 `seq:idle@0,bored@8500,idle@13000` 对移植 `idle@-640`（让移植自己的 10 分钟规则在 8.5 s 处插进 bored）：
  classic 进入 bored 后 IoU 0.956–0.962、轮廓误差 ≤1 px，回空闲后 0.948–0.974；grok 进入时 10→5 的变形、
  回去时 5→10 的变形都对上（变形中那一帧因为移植的叹气起点不落在帧上，有一帧相位差）。
- 轮廓度量修正：灰色件（offline 眼睛 alpha 0.5）用 0.5 阈值抓不到、Bresenham 斜线 4 连通会碎 →
  改成 8 连通 ＋ 移植画「纯形状」剪影对原版非黑像素。修正后所有皮肤 × 状态的确定性帧轮廓误差 ≤ 2 px。

## 第 3 轮：换状态那一刻

前两轮只看「进入某状态之后」。这一轮看**状态之间**：两张并排动图本身就是巡回（原版用 `tour:` 真的一帧帧切 FaceFrame，
移植按 `CCFaceClock` 的方式记 since 和 grokFrom），对每次切换后 0.9 s 里没在眨眼的帧逐帧比（`transitions.py`）。

结果见 `out/r3/transitions.txt`：所有皮肤的 idle→working→needs→done、classic 全部十个状态之间切换，
IoU 与各自状态的噪声底一致、轮廓误差 ≤ 2 px；grok idle→working（10→13 的弹簧变形）IoU ≥ 0.946；
例外只有两类，都是已知、有意的：grok 进入 needs（原版 −56 px 给批准气泡让位）、offline 切换时原版底部名牌浮出。

这一轮没有再发现要改的代码。

## 最终一致性

| 类别 | 内容 | 一致程度 |
|---|---|---|
| 逐帧一致（≤1–2 px） | 六套皮肤的眼睛几何、上眼皮切法（下沿 271）、全部头饰、道具位置（问号 / 打字点 / zz / 麦克风条 / 脸红 / 断线短杠 / 省略号 / o 形嘴）、呼吸 / 跳动 / 扫视 / 漂移 / zz 上飘的周期、幅度和相位、robo 高光、grok 多边形与眨眼压扁、grok 弹簧（30 fps 下 16 帧最大差 0.003）、换状态时的重置行为 | 确定性帧 IoU 0.87–0.99（差的全是抗锯齿 / 整数截断的边缘像素） |
| 统计一致 | 眨眼首次时刻、间隔、时长；表情池换脸间隔、均匀使用、不连着同一张；grok 表情池（叹气节奏 main.cpp 没跑，是对它的常数写测试钉住的） | 30 次 × 120 s 分布的均值/最小/最大全在区间内、差异在抽样误差内 |
| 有意不同 | grok needs 不上移 56 px（无批准气泡）；done 3 s（原 90 s）；颜色/材质（遮罩 ＋ 身份色金属）；连续坐标不做 `(int)` 截断；眨眼进行中换状态直接截断；打字点 3–5 个；小尺寸不画道具；surprised/petting/dizzy/eating/burp/stretch 不触发（没有传感器）；「在说话」借 petting | 都在代码注释里写了原因 |
